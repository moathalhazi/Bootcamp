# الفرق بين المكتبة (Library) وإطار العمل (Framework) في البرمجة

## 📌 مقدمة

تُعد المكتبات (Libraries) وأطر العمل (Frameworks) من العناصر الأساسية في تطوير البرمجيات، حيث تساعد المطورين على تسريع عملية البرمجة، وتقليل كتابة الأكواد المتكررة، وتنظيم المشاريع البرمجية.

وعلى الرغم من وجود تشابه بينهما، إلا أن لكل منهما طريقة عمل واستخداماً مختلفاً.

## 1. ما هي المكتبة (Library)؟

المكتبة هي مجموعة من الأكواد والدوال البرمجية الجاهزة التي توفر وظائف محددة يمكن للمطور الاستفادة منها داخل مشروعه، بدلاً من كتابة هذه الوظائف من الصفر.

**الفكرة الأساسية:** أنت كمطور تتحكم في البرنامج، وتستدعي المكتبة عندما تحتاج إلى وظيفة معينة.

### أمثلة على المكتبات

- **JavaScript:** jQuery, Lodash, Moment.js.
- **Python:** NumPy, Pandas, Matplotlib, Requests.
- **PHP:** Guzzle, PHPMailer, Carbon.
- **Java:** Apache Commons, Guava, Jackson.

## 2. ما هو إطار العمل (Framework)؟

إطار العمل هو بيئة تطوير متكاملة توفر هيكلاً وأدوات وقواعد جاهزة لبناء التطبيقات وتنظيمها.

يساعد المطور على بناء المشاريع بطريقة منظمة، ويوفر مكونات جاهزة لإدارة المهام المختلفة مثل التوجيه (Routing)، والتعامل مع قواعد البيانات، وإدارة الطلبات والاستجابات.

**الفكرة الأساسية:** إطار العمل هو الذي يستدعي الكود الذي تكتبه وفقاً للقواعد وآلية العمل التي يحددها.

### أمثلة على أطر العمل

- **JavaScript:** Angular, Express.js, NestJS.
- **Python:** Django, Flask, FastAPI.
- **PHP:** Laravel, Symfony, CodeIgniter.
- **Ruby:** Ruby on Rails, Hanami.
- **Java:** Spring Framework, Struts, Play Framework.

## 3. ما الفرق بين Library و Framework؟

| وجه المقارنة | Library | Framework |
|---|---|---|
| التعريف | مجموعة أكواد لوظائف محددة | هيكل متكامل لبناء التطبيقات |
| التحكم | المطور يتحكم في استدعائها | الإطار يستدعي كود المطور |
| الاستخدام | تنفيذ مهام معينة | تنظيم وبناء التطبيق |
| المرونة | يمكن استخدامها حسب الحاجة | تفرض هيكلاً وقواعد معينة |
| نطاق العمل | غالباً وظائف محددة | غالباً نطاق أوسع |

## 4. مفهوم Inversion of Control (IoC)

من أهم الفروقات التقنية بين المكتبة وإطار العمل مفهوم يسمى:

**Inversion of Control (IoC) – انعكاس التحكم.**

- في المكتبة (Library): أنت تستدعي المكتبة عندما تحتاج إلى تنفيذ وظيفة معينة.
- في إطار العمل (Framework): إطار العمل هو الذي يتحكم في دورة تشغيل التطبيق ويستدعي الكود الذي كتبته في الأوقات المناسبة.

وهذا هو الفرق المعروف باسم:

**Don't Call Us, We'll Call You.**

أي: لا تستدعِنا، نحن من سنستدعيك.

## 5. هل يمكن استخدام المكتبات داخل أطر العمل؟

نعم، يمكن استخدام المكتبات داخل أطر العمل بكل سهولة.

على سبيل المثال، عند تطوير تطبيق باستخدام Django في Python، يمكنك استخدام مكتبات إضافية مثل:

- Requests للتعامل مع طلبات HTTP.
- Pillow لمعالجة الصور.
- NumPy للعمليات الحسابية.

وهذا يعني أن إطار العمل يوفر الهيكل الأساسي للتطبيق، بينما تضيف المكتبات وظائف متخصصة حسب احتياجات المشروع.

## 6. أمثلة عملية من لغات البرمجة المختلفة

| لغة البرمجة | المكتبات (Libraries) | أطر العمل (Frameworks) |
|---|---|---|
| JavaScript | jQuery, Lodash, Axios | Angular, Express.js, NestJS |
| Python | NumPy, Pandas, Requests | Django, Flask, FastAPI |
| PHP | Guzzle, PHPMailer, Carbon | Laravel, Symfony, Yii |
| Ruby | RSpec, Devise | Ruby on Rails, Hanami |
| Java | Guava, Jackson, Apache Commons | Spring, Struts, Play Framework |

**ملاحظة:** بعض التقنيات قد يختلف تصنيفها حسب طريقة استخدامها وطبيعة المشروع. فمثلاً React تُصنّف عادةً كمكتبة واجهات مستخدم، وNode.js بيئة تشغيل JavaScript وليست إطار عمل.

## 7. الخلاصة

يمكن تلخيص الفرق بين المكتبة وإطار العمل في نقطة أساسية:

- **Library:** أنت تستدعيها لتنفيذ وظيفة تحتاج إليها.
- **Framework:** هو الذي ينظم التطبيق ويستدعي الكود الذي تكتبه وفقاً لقواعده.

كلاهما يساعد المطور على توفير الوقت والجهد وتحسين جودة التطبيقات، ويمكن الجمع بينهما في المشروع الواحد لتحقيق أفضل النتائج.
